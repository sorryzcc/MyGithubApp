# 翻译工作流

## 用途

在保持结构、格式与技术语义不变的前提下完成翻译，覆盖对话内文本、仓库文档、代码注释与 UI 文案。

## 触发场景

- 请求翻译选中文本、粘贴文本或对话内句子（「翻译」「translate」）。
- 请求翻译或本地化 README、Markdown 文档、代码注释、字符串文案（「汉化」「localize」）。
- 请求中英对照、术语统一、译文润色 / 校对 / 回译校验。

## 工作流

1. 确定输入与语言方向
   - 从用户消息、选中内容或指定路径取得源文本；处理文件前先完整读取。
   - 目标语言未指定时：中文用户默认英译中，中文源文默认中译英；其余按用户指定。
   - 多文件任务先列出待翻译文件与输出路径，再逐个处理。
2. 标记原样保留内容
   - 加载 `references/translation-rules.md`，按「不翻译清单」识别代码、标识符、命令、URL、占位符、语法标记与通用缩写。
   - 对不确定的专有名词保留原文，或采用「中文译名（English）」。
3. 执行翻译
   - 逐段翻译，保持段落顺序、标题层级、列表 / 表格结构、换行与缩进。
   - 同一任务内复用术语表；不增不减信息，不总结、不改写、不省略。
   - 长文件按标题分块处理，逐块核对结构，避免术语漂移。
4. 输出结果
   - 对话内文本：直接给译文；要求对照时按「原文 / 译文」逐段并列。
   - 文件：默认新建 `原名.zh-CN.md` / `原名.en.md`（或用户指定路径），不覆盖原文件；仅在明确要求原地替换时编辑原文件。
   - 代码文件：仅翻译注释与面向用户的字符串字面量，保持可编译；改完执行对应格式 / 构建检查（如 `gofmt`、`go build`）。
   - 跳过二进制与生成文件时，在交付说明中列出跳过原因。
5. 自检
   - 按 `references/translation-rules.md` 的「交付检查清单」核对条目数、代码块、链接、占位符、数字、单位、否定与条件语义。
   - 发现漏译、重复、误译或结构错位，先修正再交付。

## 边界

- 不修改用户未指定的文件，不擅自覆盖原文件。
- 不把翻译扩展为改写或润色，除非用户明确要求。
- 保留代码语法、标识符、通用缩写与占位符，属于正确性要求。

## 资源

- `references/translation-rules.md` — 不翻译清单、技术术语对照、文件命名约定、质量检查清单与常见失败处理。
- 本 skill 不需要 `scripts/` 与 `assets/`：翻译由模型完成，无需确定性脚本或输出模板。
