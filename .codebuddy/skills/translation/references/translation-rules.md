# 翻译规范

本文件供翻译执行时按需加载，包含不翻译清单、术语对照、文件约定与质量检查清单。

## 不翻译清单（原样保留）

- 代码块与行内代码、标识符、函数名、包名、类型名、API 名称、命令、flag、环境变量。
- URL、文件路径、邮箱、版本号、数值、单位、日期格式。
- 占位符与格式化动词：`{name}`、`%s`、`%d`、`{{ .Name }}`、`$ARGUMENTS`、`<placeholder>` 等。
- Markdown/HTML/YAML 语法、YAML frontmatter 的键名、HTML 属性名与标签名。
- 构建与工具指令：`//go:build`、`// TODO:`、`//nolint`、`@param` 等标签本身。
- 通用缩写与产品名：HTTP、gRPC、JSON、API、URL、CLI、SDK、Git、Go、TDesign。

## 术语处理

- 首次出现的关键术语采用「中文译名（English）」，后文统一使用同一译名；不混用多种译法。
- 项目内已有译文、术语表或既有翻译风格时，先搜索仓库并沿用，不自造新译名。
- 同一批次任务（尤其多文件、长文档）先建立术语表并全程复用，避免前后漂移。
- 用户要求时，在交付末尾附上本次使用的术语表。

## 文件处理约定

- 输出命名：`README.zh-CN.md`、`README.en.md`、`docs/guide.zh-CN.md`；文件名不得与原文件相同。
- 默认不覆盖原文件，仅在用户明确要求「原地替换 / 覆盖」时才编辑原文件，且改前先读取完整内容。
- 保持 UTF-8 编码与原文件的换行风格（LF / CRLF）、缩进宽度、标题层级、列表与表格结构。
- 图片、二进制文件与生成文件（`*.pb.go`、`go.sum`、锁文件等）跳过翻译，并在交付说明中列出跳过原因。
- 长文件按标题分块翻译、逐块写入；每块完成后核对结构，再进入下一块。
- 代码文件只翻译注释与面向用户的字符串字面量，改完执行对应检查（如 `gofmt`、`go build`）。

## 交付检查清单

- [ ] 段落数、列表项数、表格行数、标题层级与数量一致
- [ ] 代码块数量、内容与语言标记未变
- [ ] 链接 URL、占位符、命令、标识符、版本号未被翻译
- [ ] 数字、单位、否定词、条件与比较语义与原文一致
- [ ] 无漏译、无增译、无重复；未擅自总结或改写
- [ ] 术语前后一致；混合语言段落只翻译目标部分
- [ ] 输出路径正确，原文件未被意外覆盖
- [ ] 代码文件仍能格式化 / 编译通过

## 常见失败与处理

- 译文出现 `%!s(MISSING)` 或占位符错位：占位符被误改，按原文还原并逐一核对。
- Markdown 表格列错位：管道符或对齐行被改动，按原表结构重建。
- 术语漂移：长文档分块前未固定术语表，回退并统一全文译名。
- 代码注释翻译后编译失败：build tag、指令注释或字符串中的格式化动词被翻译，恢复为原文。
